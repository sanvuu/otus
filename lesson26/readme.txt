# Домашнее задание: Настройка резервного копирования с помощью BorgBackup

## Цель домашнего задания
Научиться настраивать автоматизированное удаленное резервное копирование с использованием утилиты BorgBackup, применять политики удержания бэкапов (ротации) и управлять расписанием через системные таймеры Systemd.

## Схема сети и параметры стенда
Тестовый стенд разворачивается в изолированной приватной сети VirtualBox и состоит из двух виртуальных машин на базе Ubuntu 22.04 LTS:
* **backup_server**: IP `192.168.11.160`, 2 CPU, 2GB RAM. К машине подключен дополнительный SCSI-диск размером 2 ГБ, отформатированный в `ext4` и смонтированный в `/var/backup`. Репозиторий Borg инициализирован по пути `/var/backup/repo`.
* **client**: IP `192.168.11.150`, 2 CPU, 2GB RAM. Источник бэкапов (каталог `/etc`). На этой же машине развернут Ansible для локального управления автоматизацией.

## Особенности проектирования и реализации решения

1. **Полная автоматизация без Ansible на хосте**:
   Поскольку на хостовой Windows-машине отсутствует Ansible, развертывание реализовано через встроенный механизм Vagrant. С помощью Shell-provisioner на `client` устанавливается пакет `ansible`, который локально запускает многоузловой плейбук (`ansible-playbook -i ansible/inventory.ini ansible/playbook.yml`). Это позволяет развернуть весь стенд с нуля одной командой `vagrant up`.
   
2. **Безопасное управление SSH-ключами**:
   Приватный SSH-ключ, генерируемый Vagrant на Windows-хосте, пробрасывается в общую папку `/vagrant` с правами `0777`. OpenSSH считает такой ключ небезопасным. Для обхода этого ограничения в начале плейбука реализовано автоматическое копирование ключа во внутреннюю директорию `/tmp/backup_server_private_key` с назначением легитимных прав `0600`.
   
3. **Безопасность и изоляция Borg**:
   На сервере бэкапов создан выделенный системный пользователь `borg`. Все операции резервного копирования выполняются от его имени. Доступ клиента на сервер осуществляется по SSH-ключам (публичный ключ `root` с клиента добавлен в `authorized_keys` пользователя `borg` на сервере). Репозиторий зашифрован в режиме `repokey` с использованием парольной фразы `Otus1234`.

4. **Интеграция с Systemd и логирование**:
   Автоматизация бэкапов реализована через нативный Systemd-сервис (`borg-backup.service`) и таймер (`borg-backup.timer`). В соответствии с методичкой, вся логика (создание архива, проверка `borg check` и ротация `borg prune`) выполняется последовательными вызовами `ExecStart` прямо внутри юнита, без использования внешних bash-скриптов. Логирование автоматически перенаправляется в системный журнал `journald`.

5. **Политика удержания архивов (Prune)**:
   Настроена глубина бэкапов до одного года:
   * Последние 3 месяца содержат ежедневные копии (`--keep-daily 90`).
   * Оставшийся период до года хранит по одной копии на конец месяца (`--keep-monthly 12`).
   * Хранится одна годовая копия (`--keep-yearly 1`).

### 2. Список архивов в удаленном репозитории (borg list)
Запрос списка точек восстановления с клиента подтверждает успешную физическую запись данных на сервер бэкапов:

```bash
root@client:~# export BORG_PASSPHRASE="Otus1234"
root@client:~# borg list borg@192.168.11.160:/var/backup/repo
etc-2026-10-10_17:50:06              Sat, 2026-10-10 17:50:08 [2d4e166229e6358d5c0adc010b6f797796a90250553472cc416a1afac7d74c19]
```

### 3. Статус планировщика таймеров (systemctl list-timers)
Таймер успешно инициализирован, активен и осуществляет циклический запуск службы каждые 5 минут относительного времени (`OnUnitActiveSec=5min`):

```bash
root@client:~# systemctl list-timers --all | grep borg-backup

```
