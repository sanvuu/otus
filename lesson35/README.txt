# Домашнее задание: Vagrant-стенд с DNS и Split-DNS

## Цель домашнего задания
Создать домашнюю сетевую лабораторию на базе Vagrant и Ansible. Изучить основы работы службы DNS (BIND9), репликацию зон (Master/Slave) и технологию разделения горизонтов (Split-DNS / views).

## Текст задания
1. Взять за основу стенд `vagrant-bind` и добавить второй клиентский хост `client2`.
2. В зоне `dns.lab` завести записи:
   - `web1` — указывает на `client` (`192.168.50.15`)
   - `web2` — указывает на `client2` (`192.168.50.16`)
3. Завести новую зону `newdns.lab` и добавить в неё запись:
   - `www` — указывает на обоих клиентов (`192.168.50.15` и `192.168.50.16`)
4. Настроить Split-DNS:
   - `client` (`192.168.50.15`) видит обе зоны (`dns.lab` и `newdns.lab`), но в зоне `dns.lab` видит только запись `web1`.
   - `client2` (`192.168.50.16`) видит только полную зону `dns.lab` (`web1` и `web2`) и не видит зону `newdns.lab`.
5. Дополнительное задание: не отключать подсистемы принудительного контроля доступа (SELinux / AppArmor).

## Особенности проектирования и реализации

### 1. Среда виртуализации и ОС
- Стенд адаптирован под провайдер **libvirt / KVM** на базе образа **`bento/ubuntu-24.04`** вместо устаревшего CentOS 7 / VirtualBox.
- В качестве DNS-сервера используется **BIND9** (`bind9`, `bind9-utils`, `dnsutils`).
- На клиентских машинах отключён локальный кэширующий резолвер `systemd-resolved`, а `/etc/resolv.conf` настроен статически на оба DNS-сервера (`192.168.50.10` и `192.168.50.11`), чтобы запросы отправлялись напрямую с IP-адресов клиентов для корректного срабатывания ACL в Split-DNS.

### 2. Архитектура стенда

| Хост | Роль | IP-адрес | Видимые зоны и записи |
| :--- | :--- | :--- | :--- |
| `ns01` | Master DNS | `192.168.50.10` | Все представления (`client`, `client2`, `default`) |
| `ns02` | Slave DNS | `192.168.50.11` | Репликация всех представлений с `ns01` |
| `client` | Клиент 1 | `192.168.50.15` | `web1.dns.lab`, `www.newdns.lab` |
| `client2` | Клиент 2 | `192.168.50.16` | `web1.dns.lab`, `web2.dns.lab` |

### 3. Реализация Split-DNS и репликации (Master–Slave)
- Разделение видимости реализовано через директивы `view` (`client`, `client2`, `default`) и списки контроля доступа `acl` в `/etc/bind/named.conf.local`.
- Для каждого представления используется отдельный файл зоны (`named.dns.lab.client` для `client` и полный `named.dns.lab` для `client2`).
- Чтобы `ns02` (Slave) корректно получал с `ns01` (Master) разные версии одноимённой зоны `dns.lab` для каждого `view`, трансфер зон привязан к отдельным TSIG-ключам (`client-key`, `client2-key`, `zonetransfer.key`), указанным в `acl`, `also-notify` и `server`.
- Профили безопасности **AppArmor** для службы `named` оставлены активными; файлы зон размещены в `/etc/bind/zones/` (чтение) и `/var/cache/bind/` (запись slave-зон).

## Запуск и проверка

1. Развернуть стенд:
   ```bash
   vagrant up
   ```
2. Проверить резолвинг с `client` (`192.168.50.15`):
   ```bash
   vagrant ssh client -c "dig @192.168.50.10 web1.dns.lab +short && dig @192.168.50.10 web2.dns.lab +short && dig @192.168.50.10 www.newdns.lab +short"
   ```
   Ожидаемый вывод: `192.168.50.15`, `192.168.50.15`, `192.168.50.16` (`web2.dns.lab` не резолвится).

3. Проверить резолвинг с `client2` (`192.168.50.16`) через Slave-сервер `ns02`:
   ```bash
   vagrant ssh client2 -c "dig @192.168.50.11 web1.dns.lab +short && dig @192.168.50.11 web2.dns.lab +short && dig @192.168.50.11 www.newdns.lab +short"
   ```
   Ожидаемый вывод: `192.168.50.15`, `192.168.50.16` (`www.newdns.lab` не резолвится).
